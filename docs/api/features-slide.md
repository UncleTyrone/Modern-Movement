# `features/slide.py`

Sprint-crouch slides. Network path: CrouchedPct decay plus `_coast_slide` on the entry direction (`host_enter_juso(..., distance_percent, dir_x, dir_y, speed_percent)`). A sustained drop (`_track_drop` past 0.12s) slows that decay and uses `_MAX_DOWNHILL_S`. One Z sample does not. `_distance_scale` lengths the decay. `_speed_scale` multiplies coast speed only (default 120). The coast push is `_COAST_PUSH`, and the crouch cap matches that speed. Host service and PlayerMove post both re-apply the coast. The owning client ends the slide on crouch release (`stood up` → `server_slide_exit`); the host copy does not cancel from a missing `bDuck`.

A slide jump stores `state.slide_jump`. `state.chain` and `chain_hold` are set only when `_crouch_held` is True, so an unreadable key or a leftover crouch pose does not chain. Releasing crouch clears the chain. While that chain is set, `DuckPressed` is blocked on the owning client only, and `chain_blocks_slam()` keeps Borderlands 2 slam from arming, so the held crouch is not an Oz slam or a custom slam. `_authority_tick` does not run that input machine on a joiner's server pawn. The host coast stays in `_HOST_SLIDES`. A joiner slide jump calls `server_slide_jump(vx, vy, vz)`. The host drops the coast, stands the crouch up, and holds that launch in `_HOST_JUMPS` for `_LAUNCH_HOLD` (0.15s). While the pawn is already rising, later ticks write horizontal speed only. On landing, `offer_landing` starts the next slide only when `_chain_air_ok` is true (`core.clock - at >= _CHAIN_MIN_AIR`, 0.40s). A new in-air crouch press banks `slam_bank`; `Landed` or slam `_impact` calls `offer_landing` with that speed when crouch is still held. `release_player` drops holds on respawn or travel. Slide indicator HUD. No Mesh.Z dips.
