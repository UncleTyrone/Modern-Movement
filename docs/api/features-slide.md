# `features/slide.py`

Sprint-crouch slides. Network path: CrouchedPct decay plus `_coast_slide` on the entry direction (`host_enter_juso(..., distance_percent, dir_x, dir_y, speed_percent)`). A sustained drop (`_track_drop` past 0.12s) slows that decay and uses `_MAX_DOWNHILL_S`. On that same drop the local coast keeps its speed instead of bleeding to a crouch walk. One Z sample does not. `_distance_scale` lengths the decay. `_speed_scale` multiplies coast speed only (default 120). The coast push is `_COAST_PUSH`, and the crouch cap matches that speed. Host service and PlayerMove post both re-apply the coast. The owning client ends the slide on crouch release (`stood up` → `server_slide_exit`); the host copy does not cancel from a missing `bDuck`. Borderlands 2 crouch is a toggle, so `_bl2_key_up` ends the slide when the physical key is up. That read is the keyboard key when PressedKeys omits a hold, so letting go ends the slide and a second press is not required. A held key starts the slide without waiting for a sprint-sized GroundSpeed. The sprint already held does not end it. After that key comes up, the next sprint press does, and the leftover slide time is not a lock. The Pre-Sequel still treats a PressedKeys miss as held.

A slide jump stores `state.slide_jump`. `state.chain` stays armed while `crouch_down` is set. That latch is set on DuckPressed and cleared on DuckReleased. A PressedKeys miss does not clear it, because that list omits a crouch key that is still held. The normal landing slide is blocked for 3 seconds after the jump, so the crouched pose cannot start another slide. A timed joiner slide still ignores a one-frame crouch-flag flicker. While that chain is set, `DuckPressed` is blocked on the owning client only, and `chain_blocks_slam()` keeps Borderlands 2 slam from arming, so the held crouch is not an Oz slam or a custom slam. `_authority_tick` does not run that input machine on a joiner's server pawn. The host coast stays in `_HOST_SLIDES`. A joiner slide jump calls `server_slide_jump(vx, vy, vz)`. The host drops the coast, stands the crouch up, and holds that launch in `_HOST_JUMPS` for `_LAUNCH_HOLD` (0.15s). While the pawn is already rising, later ticks write horizontal speed only. On landing, `offer_landing` starts the next slide only when `_chain_air_ok` is true (`core.clock - at >= _CHAIN_MIN_AIR`, 0.40s). A sprint jump with no slide before it stores the fastest horizontal speed in `state.air_slide` only when `air_pressed` is set by DuckPressed while falling. Landing calls `_air_crouch_landing` only in walking physics, and it slides when that speed meets Min Slide Speed and the key is still down. `_start` returns while a slide is already active, and DuckPressed during a slide is blocked, so a second press cannot stack another slide. `_end` clears `air_pressed`, `air_slide`, and `suppress_crouch_until_release`. Every slide is fresh for `_LAND_GRACE`, so the sprint already held does not end it. `_sprint_press_is_cancel` ends it once `sprint_released` is set. `_start` ignores the key-up of that same press for 0.05s on Borderlands 2 and 0.20s on The Pre-Sequel, so a timed slide does not end `stood up` on the tap that started it. A crouch edge while sprinting starts the next slide. `offer_landing` passes `core.facing` and the saved speed into `_start`, which stores that direction itself. For `_LAND_GRACE` (0.35s) the landing slide ignores stall, back-cancel, a sprint edge, and a one-frame hop, and PlayerMove gets the new coast written back. A slide jump does not use that path. An unreadable key does not slide. A slam that is still diving is not replaced by a slide. `slam_hold` is cleared every tick, so the next crouch can slide. There is no sprint wait after a slide. The slide bar is `_slide_fill`: it follows the time cap that ends the slide, and it is empty when the slide ends. A speed-only bar sat near full for the whole coast. Holding the key keeps the slide if the crouch pose drops for a frame. `release_player` drops holds on respawn or travel. Slide indicator HUD. No Mesh.Z dips. The first-person rest pose is `_ARMS_REST`. A begin does not read a tilted gun as that rest. `_settle_arms` puts an idle gun that is still at the slide angle back to level. `_ground_jump` latches crouch before `_end`, so the uncrouch's DuckReleased does not clear a joiner's chain. `DoJump` does not send a second `server_slide_exit`; `_end` already did, and `host_exit_juso` leaves a jump hold alone. The arms pose snaps back to `_ARMS_REST` and is cleared. It does not lerp from the lean. A walking frame before `_CHAIN_MIN_AIR` leaves the chain armed.
